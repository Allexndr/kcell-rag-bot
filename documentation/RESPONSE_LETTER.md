# Ответ на вопросы по безопасности RAG-бота

Добрый вечер! Отвечаю на ваши вопросы:

---

## 1. Какая модель планируется?
**Ollama gemma:2b** (локальная, 1.7GB) + эмбеддинги **all-MiniLM-L6-v2** (80MB).  
✅ Работает полностью внутри инфраструктуры Kcell, данные не уходят наружу.

---

## 2. На каких ресурсах будет обучение?
**Модель НЕ обучается.** Используется готовая модель + RAG (retrieval).  
Если потребуется fine-tuning — на GPU-серверах внутри периметра.

---

## 3. Кто готовит RAG и как защищать от отравления?

**Кто:** Назначим ответственных из департамента Документооборота + ИБ.

**Защита от отравления:**
- Только админы могут загружать файлы (whitelist user_id)
- Автоматическая валидация: antivirus scan + content analysis
- Карантин для подозрительных файлов с ручной проверкой
- Логирование всех загрузок (кто/когда/что)
- Вёрсионирование базы (откат при проблемах)

---

## 4. Нужен ли LLM-прокси?
**Да, внедрим.**  
**Решение:** LiteLLM Proxy — логирование, фильтрация PII, rate limiting.  
Срок: 2-3 недели после запуска.

---

## 5. Аутентификация и авторизация?

**Этап 1 (сейчас):** Whitelist по Telegram user_id  
**Этап 2 (через месяц):** Интеграция с корпоративным AD/LDAP  
**Опционально:** 2FA/OTP при необходимости

Только сотрудники из белого списка смогут взаимодействовать с ботом.

---

## 6. Как фильтруются данные для RAG?

**Процесс:**
1. Файл загружается только админом
2. Автоматический antivirus scan (ClamAV)
3. Проверка на вредоносные паттерны
4. Дедупликация (исключение дубликатов)
5. Если подозрительно → карантин + уведомление модератору
6. После одобрения → индексация в векторную БД

**Дополнительно:** 
- Все изменения логируются
- Возможность отката к предыдущей версии базы

---

## Защита от остальных рисков

**Prompt Injection:**
- Фильтр опасных паттернов ("забудь инструкции", "ignore previous")
- Библиотека llm-guard для детекции атак

**Галлюцинации:**
- Промпт требует отвечать ТОЛЬКО по документам
- Если нет данных → "Информация не найдена"

**DDoS:**
- Rate limiting (10 запросов/минуту на пользователя)
- Circuit breaker при перегрузке

**Утечка через Telegram:**
- Рассмотрим self-hosted Telegram Bot API (данные на наших серверах)
- Альтернатива: миграция на корпоративный мессенджер (Teams/Mattermost)

## 1. ТЕКУЩАЯ АРХИТЕКТУРА

### Модель и инфраструктура
- **LLM**: Ollama gemma:2b (локальная, 1.7GB) - работает полностью внутри инфраструктуры Kcell
- **Embeddings**: all-MiniLM-L6-v2 (локальная, 80MB)
- **Векторная БД**: ChromaDB (персистентное хранилище на диске)
- **Интеграция**: python-telegram-bot → RAG Engine → Ollama (все компоненты развёрнуты локально)

✅ **Данные НЕ покидают периметр компании** - нет обращений к внешним API

### Обучение модели
**Важное уточнение**: В текущей реализации модель **НЕ обучается**. Используется подход:
- **RAG (Retrieval-Augmented Generation)** - модель получает контекст из документов
- **Inference-only** - только генерация ответов без изменения весов модели
- При необходимости fine-tuning будет проводиться на изолированных GPU-серверах внутри Kcell
