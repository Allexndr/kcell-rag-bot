1. ОБЩИЕ СВЕДЕНИЯ О ПРОЕКТЕ
================================================================================

1.1. Наименование проекта
Kcell RAG Bot - Система Retrieval-Augmented Generation для интеллектуального поиска
и ответов на вопросы по корпоративным документам компании Kcell.

1.2. Цель проекта
Создание автоматизированной системы для быстрого и точного поиска информации в
обширной базе корпоративных документов Kcell с использованием современных технологий
искусственного интеллекта.

1.3. Задачи проекта
- Предоставление мгновенных ответов на вопросы сотрудников о тарифах, услугах и процедурах Kcell
- Автоматизация поиска в архивных документах (приказы, спецификации, договоры)
- Обеспечение конфиденциальности данных путем использования локальных моделей ИИ
- Поддержка различных форматов документов (PDF, DOCX, XLSX, PPTX)

1.4. Дата создания
Декабрь 2025 года

1.5. Авторы
Команда разработчиков Kcell

2.1. Архитектура системы

СИСТЕМНАЯ АРХИТЕКТУРА:

│   Telegram Bot  │    │   RAG Engine    │    │   Document DB   │

│   User Queries  │    │   Ollama LLM    │    │   Document      │

└─────────────────┘    └─────────────────┘    └─────────────────┘

2.2. Компоненты системы

2.2.1. Telegram Bot (main.py)
- Функционал: Интерфейс взаимодействия с пользователем
- Технологии: python-telegram-bot
- Возможности:
  - Получение текстовых запросов
  - Загрузка новых документов для индексации
  - Отправка ответов пользователю

2.2.2. RAG Engine (rag_engine_local.py)
- Функционал: Обработка запросов и генерация ответов
- Технологии: Ollama, ChromaDB, SentenceTransformers
- Возможности:
  - Расширение запросов (синонимы, сленг)
  - Векторный поиск по документам
  - Формирование контекста
  - Генерация ответов с использованием контекста

2.2.3. Document Ingestion System (ingest.py)
- Функционал: Индексация документов в векторную базу
- Поддерживаемые форматы:
  - PDF (с OCR для сканированных документов)
  - DOCX (Word документы)
  - XLSX (Excel таблицы)
  - PPTX (PowerPoint презентации)
  - TXT, RTF (текстовые файлы)

2.2.4. Vector Database (Chroma DB)
- Функционал: Хранение векторных представлений документов
- Модель эмбеддингов: all-MiniLM-L6-v2 (SentenceTransformers)
- Метаданные: источник, год, путь к файлу

2.2.5. Language Model (Ollama)
- Модель: llama3.1:8b
- Размер: 4.9 GB
- Особенности: Локальная модель, не требует интернета

2.3. Схема работы системы

ЭТАП 1: ИНДЕКСАЦИЯ ДОКУМЕНТОВ
Документы → Извлечение текста → Разбиение на чанки → Векторизация → Chroma DB

ЭТАП 2: ОБРАБОТКА ЗАПРОСА ПОЛЬЗОВАТЕЛЯ
Запрос → Расширение запроса → Векторный поиск → Извлечение контекста → Генерация ответа

ЭТАП 3: ГЕНЕРАЦИЯ ОТВЕТА
Контекст + Запрос → LLM (Ollama) → Ответ пользователю

5. АЛГОРИТМ РАБОТЫ
================================================================================

5.1. Индексация документов

1. Сканирование директории: Поиск файлов поддерживаемых форматов
2. Извлечение текста:
   - PDF: pypdf (текстовые) или OCR (сканированные)
   - DOCX: python-docx с извлечением таблиц
   - XLSX: pandas с конвертацией в Markdown таблицы
   - PPTX: python-pptx с структурированием слайдов
3. Разбиение на чанки: 4000 символов с перекрытием 500
4. Векторизация: SentenceTransformers (all-MiniLM-L6-v2)
5. Сохранение: Chroma DB с метаданными

5.2. Обработка запроса

1. Расширение запроса: Замена сленга на формальные термины
   - "револьверку" → "револьверный пакет"
   - "ватс" → "виртуальная атс"
   - "симку" → "sim карта"

2. Векторный поиск: Поиск 10 наиболее релевантных чанков

3. Формирование контекста: Извлечение текста из найденных чанков с указанием источника

4. Генерация ответа: Ollama LLM с промптом на русском языке

5.3. Особенности обработки

OCR для сканированных PDF:
- Конвертация в изображения (150 DPI)
- Распознавание текста pytesseract (rus+eng)
- Прогресс-бар для больших документов

Обработка таблиц:
- XLSX → pandas DataFrame → Markdown
- DOCX таблицы → аналогичная конвертация

Чанкинг:
- Размер чанка: 4000 символов
- Перекрытие: 500 символов
- Разрывы на границах предложений

ПРИЛОЖЕНИЕ 4: СХЕМА ПОТОКА ДАННЫХ
================================================================================

ПОТОК ДАННЫХ В СИСТЕМЕ:

ИНДЕКСАЦИЯ ДОКУМЕНТОВ:
1. Файлы → extract_text_from_*() → текст
2. Текст → chunk_text() → чанки (список строк)
3. Чанки → embedding_fn() → векторы (numpy arrays)
4. Векторы + метаданные → collection.add() → Chroma DB

ОБРАБОТКА ЗАПРОСОВ:
1. Запрос → expand_query_rule_based() → расширенный запрос
2. Запрос → embedding_fn() → вектор запроса
3. Вектор → collection.query() → релевантные чанки
4. Чанки → формирование контекста → текст для LLM
5. Контекст + запрос → generate_text() → ответ

КОММУНИКАЦИЯ:
1. Telegram → Webhook → main.py обработчики
2. main.py → RAGEngineLocal.answer_question()
3. RAGEngineLocal → Chroma DB запрос
4. RAGEngineLocal → Ollama API вызов
5. Ollama → ответ → Telegram API → пользователь

ХРАНЕНИЕ ДАННЫХ:
- Исходные документы: /база данных документов/
- Векторная БД: /chroma_db/ (SQLite + pickle файлы)
- Логи: *.log файлы в корне проекта
- Кэш: __pycache__/ директории

ПРИЛОЖЕНИЕ 7: СЛОВАРЬ ТЕРМИНОВ
================================================================================

СПЕЦИАЛЬНЫЕ ТЕРМИНЫ ПРОЕКТА:

RAG (Retrieval-Augmented Generation):
    Технология, сочетающая поиск релевантной информации и генерацию ответов
    на основе найденных данных.

Chroma DB:
    Векторная база данных для хранения и поиска эмбеддингов текстов.

Ollama:
    Фреймворк для запуска больших языковых моделей локально.

Embedding:
    Векторное представление текста в многомерном пространстве.

Chunking:
    Разбиение длинного текста на более мелкие фрагменты (чанки) для обработки.

OCR (Optical Character Recognition):
    Распознавание текста с изображений и сканированных документов.

Vector Search:
    Поиск документов на основе семантического сходства векторов.

Token:
    Единица текста в языковой модели (слово или часть слова).

Context Window:
    Максимальная длина текста, которую может обработать модель за один раз.

Fine-tuning:
    Дополнительное обучение модели на специфических данных для улучшения качества.
